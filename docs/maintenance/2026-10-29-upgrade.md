# Security and major-version maintenance — 2026-10-29

This upgrade is prepared on `codex/security-major-updates-20261029`, initially
based on OpenSensor `main` at `d963f42` and rebased onto `fade6e7` before
publication. The newer Sentry configuration and release tracking are preserved;
test environments explicitly disable Sentry delivery. The original upstream
has no additional commits to merge. All validation used isolated environments and disposable databases;
no production database, running deployment, or production secrets were changed.

The pre-existing local `uv.lock` changes were saved before upgrading. Their
missing WebAuthn dependency is included in the regenerated lockfile.

All direct Python and npm dependencies were checked against their registries.
`uv.lock` covers runtime, development, and container-only dependencies;
`package-lock.json` fixes the frontend dependency tree. The image installs
exported, hashed Python requirements and the built application wheel. Build
tools, Node, and a second system Python package installation are excluded from
the runtime image. Redis binds only to container loopback.

The old Rollup/Babel/PostCSS/Sass pipeline was replaced with Tailwind's CLI and
esbuild. The three JavaScript bundle names and their browser globals remain
compatible with the templates. Tailwind utility names and form component
precedence were migrated. SimpleWebAuthn now receives `optionsJSON` and has
tests using the real browser library with simulated credential responses.

Compatibility fixes also cover Starlette's template initialization, WTForms
choice tuples, zxcvbn's score enum, SQLAlchemy result types, Alembic path parsing,
and Typer's separation from external Click. The CLI reports missing settings
correctly and quickstart now generates the required MFA encryption key.
Development environment initialization preserves existing keys.

## Authentication and database compatibility

New passwords use Argon2id. Successful bcrypt logins transparently upgrade the
stored hash. Verification preserves the historical 72-byte bcrypt behavior,
including long and multibyte passwords; the replacement Argon2id hash covers
the full supplied password. Existing Argon2 hashes remain valid. MFA recovery
codes retain their existing bcrypt format while removing the abandoned Passlib
dependency. No password reset or bulk hash rewrite is required.

There is no new application schema migration in this change. The existing
migration chain was exercised against fresh SQLite and PostgreSQL databases.
Synchronous PostgreSQL operations now explicitly use `postgresql+psycopg`;
asynchronous operations continue to use asyncpg. TLS parameter tests cover the
new driver name.

The Compose PostgreSQL major-version change is **not an in-place database
upgrade**. The new `postgres18-data` volume is intentionally separate from the
old `postgres-data` volume. Before using it with existing development data:

1. Stop application writes and take a logical dump from the existing PostgreSQL
   14 service, including any required roles. Verify the dump can be restored.
2. Retain the old volume. Do not run `docker compose down -v` as an upgrade step.
3. Start PostgreSQL 18 on the new volume and restore the dump into it.
4. Run application migrations, verify users/clients/grants, and exercise login,
   refresh, MFA, passkeys, and the admin portal before switching consumers.

Production database upgrades should be scheduled independently of the
application image rollout. Preserve `SECRET`, `ENCRYPTION_KEY`,
`MFA_SECRET_ENCRYPTION_KEY`, signing keys, and client credentials. Test the
candidate image against a restored database in staging and retain the previous
image and database backup for rollback. Do not point PostgreSQL 14 at an 18
data directory. The previous password helper can verify Argon2, although it
would rehash successful logins back to bcrypt.

Tailwind 4 requires modern browsers (Safari 16.4+, Chrome 111+, Firefox 128+).
Confirm the supported client browser policy before rollout.

## Validation and audit results

The original checkout had 12 failing tests caused by outdated task assertions,
migration-seeded email templates, and shared ORM fixture state. These were
reproduced before the upgrade and repaired. Each test now receives its own
detached fixture graph; SQLite test databases use unique temporary paths.

Final verification covers:

- 2,116 Python tests passing in each environment: Python 3.12/SQLite,
  Python 3.14/SQLite, and Python 3.14/PostgreSQL 18.6.
- Type checking of all 302 application modules.
- Four browser-library WebAuthn tests, frontend compilation, and wheel building.
- Container startup, the migration chain, admin creation, login page and asset
  responses, and execution of a cleanup job through the real Redis worker.
- Browser sign-in, the admin user list and search, navigation menus, and the
  mobile sidebar. No console errors were observed. Corrected form borders and
  corner radii were checked after the final CSS build.
- Fresh development environment creation and repeated initialization without
  changing existing secrets.

| Audit | Before | After |
| --- | --- | --- |
| Python dependencies | 81 advisory entries across 14 packages | 0 known vulnerabilities, including development and Supervisor dependencies |
| npm dependencies | 22 findings: 13 high, 6 moderate, 3 low | 0 known vulnerabilities |

The container is **not free of known vulnerabilities**. The remaining findings
are in Debian packages, including util-linux, ncurses, and systemd libraries.
Counts are package/advisory occurrences, not unique CVEs. Rebuild and rescan as
vendor fixes become available. Scans describe the advisories known on this
date and do not replace application security review.

CI runs tests and audits before image publishing, reports all container
findings, and rejects fixable high/critical container findings. Python and npm
audits reject any known dependency vulnerability. Repository-wide Ruff lint
already has a substantial backlog; new findings were checked against the
baseline (1,185 findings remain, down from 1,187), but a clean repository-wide
lint result is not claimed. Advisory lookup across all 157 locked Python
packages, including dependencies for other platforms, also reported no known
vulnerabilities.

## Remaining constraints and follow-ups

- HTTPX remains at 0.27.2 because the latest `fief-client` release (0.20.0)
  requires `<0.28`. Maintaining or replacing that client is a separate change;
  its requirement has not been overridden. The selected version has no known
  advisory in the current audit.
- Python 3.15 is excluded because `zxcvbn-rs-py` has no compatible wheel and its
  PyO3 source build rejects Python versions above 3.14. Revisit when that
  dependency supports 3.15.
- The product-attributed authentication history request is recorded in
  [TODO.md](../../TODO.md). Token events need client IDs and product mapping;
  login, refresh, and actual product usage must remain distinct.
- PostgreSQL/SQLite were tested; MySQL and external mail/OAuth providers were
  not exercised against live services. Passkey tests cover library behavior,
  server verification, and routes; physical authenticator testing remains a
  staging check.

Local logs, JUnit reports, lockfile backups, and audit JSON are retained under
`/tmp/fief-upgrade-20261029/`. Reproduce the checks with the commands in
[README.md](../../README.md) and `scripts/smoke-container.sh`.
